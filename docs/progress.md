## Agent loop isolation (2026-10-14)

`scripts/agent_loop.py` acceptance checks no longer inherit the operator's full environment. They receive only toolchain variables (`PATH`, `HOME`, locale, Go/Bun cache and proxy settings) plus owner `check_env`. `GOOGLE_APPLICATION_CREDENTIALS` names a missing file and `CLOUDSDK_CONFIG` an empty private directory, so worker-written tests cannot reach the production Firestore through the operator's application default credentials. `check_env` refuses `GOOGLE_*`/`CLOUDSDK_*` and is part of the check-policy fingerprint. The worker no longer has a bare `Read`/`Glob`/`Grep` allow rule and sets `blockReadsOutsideWorkingDirectories`.

Verification: 19 agent-loop tests pass (3 new). Full `make ci` passed when run under the scrubbed check environment. A Go probe found application default credentials under the operator environment and none under the check environment. A live Claude CLI 2.1.287 probe (Haiku, $0.016 total) read a file inside the worktree and was refused a canary file in its parent directory, with both the new and the previous settings. The previous bare `Read` rule was therefore not exploitable on that version; the explicit fence is hardening that no longer depends on it.
