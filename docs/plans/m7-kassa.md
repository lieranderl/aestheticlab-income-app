## Global Constraints
- Money is int64 cents; every formula lives in internal/domain. Reuse existing Store.RecordMovement/ConfirmMovement/VoidMovement/Recount/Balances; do not duplicate financial write logic.
- Employees only read/write their own data. Admin alone confirms movements, pays out, recounts and sees salon balances.
- Russian only, gender-neutral glossary from mobile-ui. 375 px, no horizontal scroll, ≥44px targets, ≥16px inputs, light/dark themes. Semantic daisyUI tokens; no inline style or custom JS.
- Native dialog bottom sheets enhanced by Datastar, with plain HTML forms and fallback GET pages so JS-disabled flows work. Never interpolate user data into Datastar expressions. Limit forms to maxFormBytes and reuse navigate/formFailed helpers.
- Financial writes use existing transactional audit and optimistic versions; closed-month writes are rejected. Failed writes preserve entered values and show actionable Russian errors. Do not expose internal errors or password/session fields.
- TDD at HTTP and public store seams, vertical slices. Full make ci and Firestore emulator tests required. Generate templ/CSS as required. Every actionable GitHub review comment must be fixed before merge.

1. Admin GET /admin/kassa replaces placeholder. Cash/card balance cards with last recount date, «Пересчитать», outstanding certificates and negative warning, pending list with one-tap confirmation, «+ Движение» sheet, recent movement cards and history link.
2. Admin movement form: payout, deposit, expense from account or person, transfer between distinct accounts. Date (start through today), amount, source/destination choices relevant to type, expense category and required note on expenses. UI never offers opening/accrual/adjustment directly. 3. POST /admin/movements records admin input; POST /movements records only own deposit or own-paid expense. Staff must not select or forge another person; reject attempted foreign ownership. GET /admin/movements/new and GET /movements/new provide non-JS fallbacks; the forms should also appear in native bottom sheets on kassa/my screens. On success navigate to /admin/kassa or /my respectively with saved notice.
4. POST /admin/movements/{id}/confirm checks submitted version, admin role, pending status and open month via Store. Both SSE and plain modes. Stale/double actions do not silently succeed; show the conflict on a safe action form/page.
5. GET /movements/{id}/void and POST /movements/{id}/void: reason required; admin can void non-accrual rows in open months; staff only their own pending rows. Do ownership check before rendering so another person's row is never disclosed. Display void reason and status; never delete rows. Native reason bottom sheet when practical, with fallback page/link.
6. GET /admin/accounts/{id}/recount and POST same path: counted amount (0 valid), expected amount display, note required only when different; store recomputes on submit. Native bottom sheet from kassa and fallback page. Show saved expected/count audit amounts via existing renderer. Recount changes only the selected account and writes an adjustment when necessary.
